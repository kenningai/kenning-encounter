# v0.12.0 — restarts without reconnecting, and an agent handed its own session id

No migration and no change to the ontology. Everything here is described and
tested only as part of an agent bound to its memory through Claude Code hooks,
the one configuration this project supports.

## New, opt-in: stateless HTTP

HTTP sessions stay **stateful by default**. Set
`NEO4J_MCP_SERVER_STATELESS=true` (or pass `--server-stateless`) to run the
server without MCP sessions. It is off unless you turn it on, and
`compose.yml` passes the variable through with `false` as the default.

**Why you might want it.** A stateful server holds its sessions in memory, so
restarting it (an upgrade, a redeploy) erases them. If the connection between
Claude Code and the server does not start a new session, and a stdio bridge
such as supergateway does not, every call fails until you reconnect with
`/mcp`. A stateless server issues no session, so a restart leaves nothing to
go stale. Tested through supergateway: with stateful sessions the first call
after a restart fails with `404 Session not found`; with stateless it
succeeds.

**What it costs.** The agent's continuity never depended on the transport
session. It lives in the graph, keyed by the harness session id. In stateless
mode every call that writes to a session must pass `session_id`, and
`advance_encounter` refuses a call without one rather than start a session
nothing could address again. Read-only calls are unaffected.

## New: a SessionStart hook that hands the agent its session id

`scripts/kenning_encounter_session_start_hook.py` prints the re-entry
instruction together with the harness session id Claude Code passes to the
hook. Wire it as a SessionStart command hook, and the agent has the identity
it needs for `advance_encounter`, `create_entities` and `close_encounter`
from its first turn. With no session id in its input it prints the
instruction alone, and it always exits 0, so it can never block a session
from starting.

## Fixed: the operations manual named a removed parameter

The HOWTO told agents to recover from a server restart by passing the
encounter's name in an `encounter` parameter, which the v0.10.0 process-layer
change removed. An agent following it would have made a call the server
rejects. The invariant is rewritten: pass `session_id` on every advance,
write and seal; it survives a restart and a `/resume`, and it only ever
reaches your own session's encounters.

## Changed: the re-entry payload's unsealed rows

`dissolved_at` no longer appears as a `null` on every unsealed row. Nothing
has written it since v0.10.0, so the key now appears only on encounters that
still carry the mark from before. If you read that field, treat its absence as
"never marked".

## Upgrading

Pull and rebuild. There is no migration, and nothing changes unless you opt
into stateless.
