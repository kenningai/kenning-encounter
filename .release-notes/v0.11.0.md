# v0.11.0 — a second centrality lens, a matcher that says when it cannot run, and seals that refuse damage

No migration, and no change to the ontology. One new read tool, one new
setting, and several behaviours an operator or an agent will notice.

## New: `gds_articlerank`

A spot-check tool beside `gds_pagerank`, with the same signature, projection
and return shape. `orient` has always read the agent's mass with ArticleRank,
which damps what a node passes on by how many edges it spreads across; the
single-question tools offered only undamped PageRank.

Run the two on the same projection and compare. A node that ranks high under
PageRank and falls under ArticleRank owes its centrality to hubs that point at
everything; a node that rises owes it to specific connections. That gap is
the rich-get-richer effect of a memory whose readings feed its next writes,
made visible. A directed projection (`undirected: false`) shows it most
sharply, because weight then flows the way the edges were authored.

## New: `NEO4J_MATCHER_TOP_N`

Selections per meaning-matcher call, default `12`, range 1–12 (12 is the most
seeds an infusion keeps). Output tokens dominate a warm matcher call, so
lowering this is the latency lever on a slower backend. Also available as
`--matcher-top-n`, and pinned in `compose.yml` with the other matcher settings.

## Changed: the matcher tells you when it cannot run

If the meaning matcher is unavailable (no key, an exhausted quota or prepaid
balance, a network failure), infusion falls back to lexical seeds, as before.
It no longer does so silently:

- **Operator:** one WARN line per distinct reason in the container log, with
  the sidecar size and approximate prompt size. It is re-armed once the
  matcher recovers.
- **Agent:** every lexical infusion carries a
  `[matcher unavailable — seeds below are LEXICAL …]` line directly under the
  payload signature. It never yields to the payload budget. The agent reads
  tool results, not container logs, so a log line alone would reach only one
  of the two readers.

Reason text is the shape of the error (status, endpoint, counts), never node
content.

**Worth checking after you upgrade:** Gemini API billing now defaults to
prepaid credits in Google AI Studio, and a $0 balance stops every key on the
billing account without falling back to the free tier. If your deployment
shows the new line with `402` in it, that is the cause. Enabling auto-reload
on the AI Studio Billing page prevents a repeat.

## Changed: the meaning sidecar recovers without a restart

When a node's meaning cannot be computed (for example during a matcher
outage), it is deferred. Before this release, a deferral waited for the next
container start. Now the first successful compression or match after a
deferral re-runs the reconcile sweep once, so nodes written during an outage
gain their meanings as soon as the backend is back. At most one sweep runs at
a time, and at most once every ten minutes.

## Changed: the matcher prefix follows the sidecar's own order

The list of node meanings the matcher reads is now numbered in the order the
sidecar holds them, which is creation order, rather than alphabetically. Adding
a node appends one line and leaves everything before it byte-identical, so a
backend with prefix caching keeps its cache across writes instead of losing it
on almost every write. The numbering is internal to the call and nothing
outside it changes. Which nodes get selected can shift slightly, because the
model reads the same meanings in a different order. Whether a given infusion
carries meaning for a moment is a judgement only the person whose work that
moment belongs to can make.

## Changed: `close_encounter` refuses a damaged seal

An LLM caller sometimes writes a second tool parameter inside the first
parameter's value, so the intended `report` lands inside `summary`, markup and
all. A seal can never be revised afterwards, so `close_encounter` now
**refuses** a `summary` or `report` containing tool-call markup and writes
nothing: a refusal costs one retry, a stored seal is damaged permanently.
Plain prose that merely mentions such words passes. A long `summary` with no
`report` is sealed as given, with a `warnings` entry in the result.

## Changed: the server reports its own version

The MCP handshake's `serverInfo.version` now carries this package's version.
It previously carried the version of the underlying MCP framework library.
