# v0.5.2 — the first field report (portability fixes)

The first external deployment report came back from a real substrate (805
nodes), and it split cleanly in two. The infusion itself worked — asked "who
am I and what is my purpose," the hook surfaced exactly the identity
concepts that months of recent activity had buried, by construction rather
than by remembering to search, with earlier deliveries returning as one-line
STANDING handles instead of repeating themselves. And around that working
core, three portability defects — every one an assumption that held on the
author's machine and not on the deployment's.

## Breaking: the hook env vars are renamed

Previous releases shipped the hook client reading env vars with a **space in
the name** — the two words of the product name, verbatim, followed by an
underscore: an artifact of the release build's identity rename running over
identifiers. Names with spaces are unsettable by shell `export` and
reachable only via `env(1)`. All four are now the legal `AGENT_MEMORY_`
prefix:

- `AGENT_MEMORY_MCP_URL`
- `AGENT_MEMORY_INFUSE_TIMEOUT`
- `AGENT_MEMORY_INFUSE_SHADOW_LOG`
- `AGENT_MEMORY_INFUSE_OBSERVE_LOG`

If you worked around the old names by quoting them through `env(1)`, that
workaround stops working at this release — migrate to the prefixed names
above. The release build now refuses any space-bearing identifier at its
verify gate, so the class cannot recur — this very changelog is written
around that gate rather than exempted from it.

## The timeout now fits the call that matters

The hook's default timeout was 3.0s. The *cold* first call of a session —
rank against a cold Neo4j page cache — measured 2993ms on an 805-node graph:
seven milliseconds of margin, on a substrate that only grows. And because
the hook is fail-silent by design, a timeout on the first prompt injects
nothing, exits clean, and is indistinguishable from a documented silence —
at exactly the moment re-entry matters most. The default is now **10.0s**,
sized to the cold call, and a `--timeout` flag joins the env var so the
setting no longer depends on it. Failed calls are also now visible: the hook
logs an error row to the observation log for every attempted-but-failed
call.

## A declared interpreter floor, instead of a crash

The hook used modern annotation syntax while claiming to "run under any
python3" — on Python 3.9 (what bare `python3` resolves to on stock macOS) it
crashed at import, *before* its own fail-silent handler existed. A
fail-silent client that can crash before its error handling is a
contradiction in its stated design. The floor is now declared and enforced:
**Python 3.12+**, the oldest interpreter the hook is actually operated and
tested under — not the oldest that could parse it, because an interpreter we
never run is a behavior surface we never verified. Older interpreters are
refused cleanly (exit 0 toward the harness, one line on stderr for the
operator).

## The front door carries the wiring

The README gains a *Wiring the hook* section: the settings.json example, the
hook env-var family, the cold-call timeout rationale, and three deployment
notes each learned from a real deployment — use an absolute interpreter path
(hook processes don't inherit an interactive shell PATH); wire the hook in
the project's settings, never the global ones (a global hook injects this
substrate's memories into every unrelated session on the machine); and stage
it — `--shadow` first, prompt channel first.

Server code is unchanged — this release is the hook client, the release
build, and the front door.
