# v0.9.0 — the project is renamed to Kenning Encounter

**This release renames the package.** No server behaviour changes; every tool,
type, edge, and payload is byte-identical to v0.8.0. What changes is the
identity, and it changes everywhere at once.

## Breaking: what you must update

| Before | After |
|---|---|
| `mcp-agent-memory` (package, script) | `kenning-encounter` |
| `mcp_agent_memory` (module, imports) | `kenning_encounter` |
| `scripts/agent_memory_infuse_hook.py` | `scripts/kenning_encounter_infuse_hook.py` |
| `AGENT_MEMORY_MCP_URL` | `KENNING_ENCOUNTER_MCP_URL` |
| `AGENT_MEMORY_INFUSE` | `KENNING_ENCOUNTER_INFUSE` |
| `AGENT_MEMORY_INFUSE_TIMEOUT` / `_SHADOW_LOG` / `_OBSERVE_LOG` / `_TRAJECTORY_TURNS` | `KENNING_ENCOUNTER_INFUSE_*` |
| `NEO4J_AGENT_MEMORY_PASSWORD` | `NEO4J_KENNING_ENCOUNTER_PASSWORD` |
| `agent-memory://howto` | `kenning-encounter://howto` |
| Neo4j database `agent-memory` | `kenning-encounter` |
| `github.com/kenningai/mcp-agent-memory` | `github.com/kenningai/kenning-encounter` |

**The database rename orphans existing data.** A default `compose up` now creates
and uses a database named `kenning-encounter`; an existing graph is still sitting
in `agent-memory` and will not be found. To keep it, either set
`NEO4J_DATABASE=agent-memory` explicitly and keep using the old database, or
copy the data across before switching. Nothing is deleted by the upgrade — but
nothing is migrated either, and a fresh start looks identical to a successful
one until you notice the graph is empty.

The API surface is untouched: `Encounter`, `NEXT_ENCOUNTER`,
`advance_encounter`, `RECORDED`, `CONSULTED`, `ABOUT`, `GROUNDS`, `SUPERSEDES`
and every tool name are unchanged.

## Why

"Agent memory" describes a category of software. It does not identify this one,
and a name that describes is interchangeable with every other member of its
category by construction. Worse, the category is wrong: this is not a retention
-and-retrieval layer that happens to use a graph. It is an encounter-sequential
substrate whose temporal causality is integrated rather than borrowed, and
accepting the memory comparison class concedes exactly what makes it different.

`TRADEMARKS.md` states plainly that **"agent memory" is generic and unclaimed** —
anyone building such a thing is entitled to call it that, and this project's
earlier use of it as a package name is abandoned rather than reserved. That
statement would be incoherent while the installable package was still named it.

## New documents

- **`NOTICE`** — copyright, what the work is, and the attribution and trademark
  notice. Because the Licensor has now included one, licence section 5.1
  requires you to pass it on; 8.1 makes that a condition of the grant.
- **`TRADEMARKS.md`** — what is claimed (`Kenning`), what is expressly *not*
  (the word "kenning", "agent memory", "encounter-sequential semantic graph",
  and the entire vocabulary of the interface), what you may do without asking,
  and how to ask.
- **`WITHHELD.md`** — the anticipatory layer is not in this repository, on
  purpose. Read the absence correctly: what you have is retentional by
  construction, not retentional because the rest is unfinished.
- **`SECURITY.md`** — how to report, and the one property you most need to know:
  the graph is trusted input by construction. Infusion places held content into
  the model's context, so **write access to the database is equivalent to write
  access to the prompt.** Grant it to exactly the agent whose substrate it is.
- **`CITATION.cff`** — cite the paper, not just the software.

## Also fixed

- **The README documented a flag that no longer exists.** The hook configuration
  showed `--mode full`; `--mode` was removed in v0.8.0, whose own notes tell you
  to drop it from every hook command — and the README was not updated to match.
  A stale flag has degraded to working infusion rather than a blocked prompt
  since that release, but the front door was still teaching it.
- **"the Agent Memory never races an unready database."** The product name is a
  proper noun and took no article, but every release to v0.8.0 rendered it with
  one. Fixed throughout, in both directions — the article correctly survives
  where the name is attributive ("The Kenning Encounter graph is small").
- `.DS_Store` no longer ships.
