# v0.5.3 — the hook learns its harness; extraction learns its transport

Two fixes to the governed-infusion pipeline, both found by running it in real
harnesses rather than by reading code.

## Full-mode entrypoint gate (hook client)

In a scheduled, headless harness (a cron- or workflow-driven agent), the
ritual trigger plus a session-scoped delivery ledger meant the same full-mode
payload arrived at full weight every run, forever — a drone, not recall. The
hook client (`scripts/agent_memory_infuse_hook.py`) now gates **full mode**
on an interactive entrypoint, keyed on `CLAUDE_CODE_ENTRYPOINT` (`cli` =
interactive; `sdk-cli` = headless):

- Detection is **positive**: an unrecognized harness degrades toward
  silence, never toward the drone.
- Every suppression is **recorded** in the observe log (`skipped: true`,
  `skip_reason: non-interactive entrypoint`) rather than hidden.
- The gate short-circuits **before any network call**.
- **Delta mode is never gated** — silence-as-answer already governs it.

New test module `tests/unit/test_infuse_hook.py` pins both sides of the
gate's behavior.

## Extraction envelope hygiene

Focal-signal extraction was spending real seed budget on the transport
around the content: harness-minted identifiers (`mcp__*` tool names,
`toolu_*` tool-use ids — identifier-shaped, so they rode the hard-signal
weight), the hook envelope's own structural field names (`type`, `text`,
`tool_use_id`, notification tags), and unicode-escape fragments (a
serialized em-dash arriving as the literal token `u2014`). All three classes
are now refused at extraction.

Deliberately **not** filtered: bare common words that double as envelope
keys (`status`, `output`, `result`…) — they are also real prose, and
over-filtering costs recall. Tests are two-sided: transport refused, real
snake_case/kebab-case domain identifiers of the same shape survive.

No schema change; no migration. Drop-in for any v0.5.x deployment.
