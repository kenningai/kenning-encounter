# v0.7.0 — the meaning matcher: selection learns to read

A major departure from v0.6.0 under the hood. v0.6.0 made *delivery*
temporal; v0.7.0 replaces what feeds it: full-mode **selection** is no
longer lexical. The keyword pipeline that matched surface tokens against a
self-authored corpus has been superseded by a meaning matcher — and the
path there was measured, not designed in one sitting.

## Why: the level gap

A self-authored memory graph defeats lexical retrieval by construction. Its
node names are syntheses — written deliberately *above* the vocabulary of
the observations that ground them, because that lifting is what a concept
is. At a decision point, the memory that matters most is the one that bears
as an **unnamed constraint**: the agent is about to re-make a mistake its
own past corrected, in words that share nothing with the correction. No
stopword tuning, reranking, or query rewriting reaches this, because every
such fix is downstream of the level mismatch.

Three designs were measured to failure on held-out decision-point cases
with targets named in writing before any run:

- **Lexical matching (the v0.6.0 pipeline): 2/8 recall at top-30** — and
  the misses were recall failures, not ranking failures: the correct node
  never entered the candidate set, which rules out reranking entirely.
- **Frozen late-interaction embeddings: dead at a negation kill switch** —
  ranked *"produces concentration, not expertise"* above the claim it
  inverts, with the whole corpus compressed into a five-percent score band.
- **Query rewriting (lift the prompt to abstraction level): 4/8** — double
  the baseline, still failing, with the diagnosis that mattered: the lifted
  phrases were semantically right *in a different idiolect*. Two
  vocabularies at the same altitude still share no tokens. And blending
  lifted with surface seeds was *actively harmful*, destroying three of the
  four hits lifting alone had won.

## What shipped

**The meaning-maker becomes the matcher.** Offline, one model
(`gemini-3.5-flash-lite`) compresses every node's name+description into a
one-sentence meaning — the **sidecar**, a derived file living inside the
stack's own named volume, never node properties: the graph remains entirely
the agent's own writing. Per prompt, the *same model* — single-voice
authorship is what closes the idiolect gap — reads all compressed meanings
as a cached prefix plus the session **trajectory** (the last N user turns,
parsed host-side by the hook client: meaning is temporal, and a
single-prompt snapshot under-determines it) and selects the nodes that bear
on the current moment.

Measured on a fresh held-out set (targets pre-named, scored once): **recall
7/8** vs the 2/8 baseline, three targets at matcher rank 1, the trajectory
alone converting two cases no snapshot method reached, p50 ~1.3s with
prefix caching engaged. The one miss surfaced at rank 28 — found but not
ranked — and is scoped honestly: it required *disposition* (felt unease
before any query), which is not a retrieval faculty and is not chased here.

The selections seed the **unchanged** governed pipeline: frontier bias,
concept-cluster expansion, the biased rank, conflict triage, temporal
progressions, and the renewal economy are byte-identical to v0.6.0. On any
matcher failure — missing key, timeout, transport error, malformed output —
selection falls back to the original lexical path and the result reports
`selection_channel: lexical_fallback`. The matcher can never block a turn.

**The sidecar maintains itself.** Nodes are meaning-made into the sidecar
at creation (background, fail-silent); a startup reconcile sweep — content-
hash and prompt-version aware — rebuilds any gap from the graph, including
a first boot from empty; deletions drop entries. There is no maintenance
step and no host file: the whole substrate is one `docker compose up`.

**`infuse_meaning`** ships as the matcher's diagnostic surface: ranked
selections plus resolved pipeline candidates for an authored trajectory,
without payload assembly — the instrument the recall gates were scored
with, kept so they can be re-run.

## What this requires, and a word on the constraints

A **Gemini API key** (`GEMINI_API_KEY` in `.env`). Without it the server
runs fully — selection just stays on the lexical fallback and says so.

The configuration is deliberately opinionated: the model, the 5000ms
timeout (sized to the measured reasoning tail — the slow selections are the
arc-dependent ones that justify the mechanism, and a cap trimmed to the
median kills exactly the calls buying the most), the bare-numbers output
(per-selection reasons cost ~2.5s at top-30, measured), and the
same-model-both-sides rule were all reached through extensive
experimentation, with the negative results recorded as carefully as the
positive. The endpoint and model are configurable if you wish to point at a
different inference API — but the constraints are load-bearing, and if you
deviate from the measured configuration you are re-running our experiments
without our instruments. You are welcome to try.

## Mechanics

- New env family: `GEMINI_API_KEY`, `NEO4J_MATCHER_MODEL`,
  `NEO4J_MATCHER_ENDPOINT`, `NEO4J_MATCHER_TIMEOUT_MS`,
  `NEO4J_MATCHER_SIDECAR`; hook-side
  `AGENT_MEMORY_INFUSE_TRAJECTORY_TURNS` (default 7).
- `infuse` gains a `trajectory` parameter (supplied by the hook client,
  which parses the harness transcript host-side and strips tool results and
  injected reminders — the trajectory is what the person said).
- Compose gains the `sidecar_data` named volume; `scripts/` gains the
  offline sidecar builder (a dev tool — deployed stacks self-maintain).
- Every infuse result carries `selection_channel` and matcher metadata
  (latency, cached-token counts, trajectory shape) for observability.
- No embeddings, no vector index, nothing vector-shaped stored — unchanged.
