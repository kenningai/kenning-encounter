# v0.14.0 — the thread, rebinding, and a frontier that reads only what is live

One change to the process layer that needs a one-time migration, one new
edge, and three changes to what the trajectory reads back. Read
**Upgrading** before you redeploy: an existing graph has to be threaded.

## New: the thread (`NEXT_TICK`)

Sessions of one trajectory can run at the same time, and each keeps its own
chain of encounters (`NEXT_ENCOUNTER`). Until now nothing said how two
encounters in different sessions stood to each other. Every encounter
opening was already made one at a time under the server's lock, so the order
existed. It just wasn't written down.

- Every opening now takes an integer `tick`, and `NEXT_TICK` links it to the
  opening before it, whatever its session. The edge is written inside the
  same lock, from the thread's end, so two openings can never tie and no
  clock is read. `advance_encounter` returns the `tick`.
- `close_encounter` takes the same lock and records `seal_tick`: the latest
  tick at the moment of sealing. Together they place where an encounter
  began and where it was sealed among every other session's openings. No
  duration is stored, and an encounter nobody sealed keeps an open end.
- Within one session the thread follows that session's own chain. Across
  sessions it orders openings without making one session the continuation
  of another: `NEXT_TICK` between sessions means "opened before", not "went
  on to".
- `NEXT_TICK` is written only by the server, like the rest of the process
  layer, and it is left out of every coherence read and graph projection.

## New: `REBINDS`

A later Observation or Question can now take up an earlier one of the same
type: `{"type": "REBINDS", "source": <later>, "target": <earlier>,
"properties": {"why": "..."}}`, with `why` required. The earlier node is not
displaced. It stays whole, and the later node is the reading it became. Use
it to revise a noticing without overwriting it in place, or to reshape a
question. `SUPERSEDES` stays as it was, for claims (Concept, Hypothesis,
Note), because a claim can be displaced.

## Changed: what the trajectory reads back

- **Only the latest node of a chain is live.** The unanswered-Questions
  frontier skips a Question a later one `REBINDS`. The other frontier cuts,
  re-entry's live Hypotheses and infusion's conflicts skip a claim something
  `SUPERSEDES`, and any claim marked `retired` or `falsified`. The server
  never changes a status to do this; it reads the edges. The mass readings in
  `orient` still cover the whole graph.
- **A Concept arrives with its history.** `search` and `find_by_name` return
  every Concept with the coherence links around it, incoming ones included
  (`edges`, with `edge_count` beside them). What superseded a Concept, and
  what grounds it, sits next to its name.
- **`create_entities` checks the whole batch before writing anything.** An
  error now means nothing was written. For an existing node it returns the
  encounter that node was first written in, as `anchored_to`; before, that
  field was empty.

## Upgrading

1. **Rebuild and restart:** `docker compose up -d --build`.
2. **Thread your history once.** Until you do, re-entry reports
   `thread_unmigrated` and new openings take no tick:

       docker exec kenning_encounter-mcp python -m kenning_encounter.migrate_thread
       docker exec kenning_encounter-mcp python -m kenning_encounter.migrate_thread --apply
       docker exec kenning_encounter-mcp python -m kenning_encounter.migrate_thread --verify

   The first command is a dry run. The migration rebuilds the order from
   each encounter's `t_exist`, lets the graph's own chains win where a stamp
   disagrees, marks every rebuilt edge `rebuilt_from: 't_exist'`, and runs
   as one transaction under the server's lock. A mismatch rolls it back and
   writes nothing. The upgrade section of the README has the details.
3. Coming from v0.9.0, run `kenning_encounter.migrate --apply` first.

As with everything here, this is described and tested only for a trajectory:
a model bound to its memory through Claude Code hooks.
