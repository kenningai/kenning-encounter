# v0.15.1 — the thread migration scales to long histories

One change, to `python -m kenning_encounter.migrate_thread`. What it writes
is unchanged.

## Changed: seal ticks are computed in O(n log n)

The migration runs in one transaction under the advance lock, so while it
runs no session can open an encounter. Computing each sealed encounter's
`seal_tick` used to scan the whole thread once per seal, which grows with
the square of the history: seconds at a few thousand encounters, minutes
at tens of thousands. It now sorts once and searches per seal, and takes
milliseconds at those sizes.

## Upgrading

Nothing to do if your history is already threaded. If you are coming from
v0.13.x or earlier and have a long history, upgrade to this release before
running the migration; the procedure in the README is unchanged.
