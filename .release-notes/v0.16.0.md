# v0.16.0 — a third matcher voice, hooks installed from a release, and a word about backups

A new matcher voice, two changes to how every voice is asked, an installer
for the hooks, and a README section this project should have had from the
start. No migration. Read **Upgrading** if you wire the hooks from your
clone, or if you run an older Gemini model as a voice.

## Read this first: back the graph up

The README has a new section, **Back the graph up**. The graph is the
trajectory, and nothing regenerates it: the sidecar rebuilds from the graph,
and the graph rebuilds from nothing. In the Docker stack it sits in one
named volume on one machine.

This project ships no backup tooling, and how you keep copies is yours to
decide. The section says what any answer has to cover: dump with the
database stopped, keep a copy off the machine, restore a copy to prove it,
and make a failed run reach a person.

## New: an Anthropic voice

A third voice, on the same terms as the other two.

- `ANTHROPIC_API_KEY` (environment only) turns it on. With no key there is
  no voice and nothing changes.
- `NEO4J_MATCHER_ANTHROPIC_MODEL` (default `claude-haiku-5-5`) and
  `NEO4J_MATCHER_ANTHROPIC_ENDPOINT`, or `--matcher-anthropic-model` and
  `--matcher-anthropic-endpoint`.
- `NEO4J_MATCHER_LEAD` accepts `anthropic`. The voices that do not lead are
  the fallbacks, in the order gemini, openai, anthropic.
- It keeps its own sidecar, stamped with its model, and refuses any other.
  `scripts/build_meaning_sidecar.py --provider anthropic` builds it ahead of
  time; otherwise the startup sweep does.
- `infuse_meaning`'s `voice` accepts `anthropic`.

It runs as the model ships, with no thinking, effort or sampling setting,
so it reasons when it judges it should. Expect several seconds a call over
a full sidecar, against one to four for the other voices. Inside the
default budget it will usually be skipped as a fallback; to lead with it,
raise `NEO4J_MATCHER_TIMEOUT_MS` and keep the hook's timeout above that.

**Do not use as a voice the model your agent runs on.** The matcher is a
second reader of what the agent wrote, and a copy of the author is not one.

## Changed: how a voice is asked

- **The header no longer asks for a reason per line.** The request that
  closes the prompt asked for numbers only, and the header above it asked
  for reasons; some models followed the header and spent seconds writing
  them. The closing request alone now says what form the answer takes.
- **The Gemini voice's answer is held to a JSON schema**: a list of exactly
  as many integers as were asked for. There is no setting. It fixes the
  form of the answer and not the answer, which still varies between
  identical calls. The other voices are asked for plain lines.
- **No `temperature` is sent to a Gemini voice.** Current Flash models
  ignore it and Google says later ones will refuse it.
- **A selection that is only the head of the list, in order, is refused**
  and the next voice is tried. It is a model declining the task in the
  shape of an answer.

## New: install the hooks from a release

`scripts/kenning_encounter_install_hooks.py` copies both hooks out of git at
a tagged release into `~/.kenning_encounter/hooks`, refuses an untagged ref,
and records what it installed in `SOURCE.json`. `--check` exits 1 if the
copy has drifted.

Installed this way, the session-start hook compares the copy with the same
files at your clone's `main` each time a session starts. It prints `HOOKS
STALE` when a newer release changed a hook, `HOOKS ALTERED` when the copy
was edited after install, and `HOOKS CHECK UNREADABLE` when it could not
tell. A release that leaves the hooks alone raises nothing. Run from the
clone with no manifest, the hook prints what it always did.

The HOWTO tells the trajectory to raise any of those lines with you first.

## Changed: the comparison instruments

- `scripts/matcher_t0.py` gains the Anthropic arms, contrasts for every
  pair of voices, crossed arms (one voice matching over meanings another
  wrote) and raw arms (matching over the opening words of each description,
  with `--nodes`). It keeps what each call selected as positions, never as
  names, and reports agreement between arms and across repeats. An auth or
  billing failure now pauses an arm as a rate limit does.
- A defect fixed in its retry rule: it looked for a status code anywhere in
  an error, so a malformed answer of the wrong length could have been
  retried as a provider failure. It now reads the status where the HTTP
  error writes it.
- `scripts/matcher_copy_rate.py` (new) measures how much of each sidecar
  meaning is lifted word for word from its node. Counts and percentiles
  only, never node text.

## Upgrading

- **Hooks.** If your `settings.json` points at the hooks in your clone, they
  keep working. To get the drift check, run the installer and point the
  wiring at `~/.kenning_encounter/hooks`; the README shows both entries.
- **First call after the upgrade.** The matcher's prompt prefix changed, so
  each provider reads it cold once. The sidecars are untouched.
- **Older Gemini models.** A model that honoured `temperature: 0` now
  samples at its default.
- **No new setting is required.** Without `ANTHROPIC_API_KEY` the stack
  behaves as it did, apart from the changes under "how a voice is asked".
