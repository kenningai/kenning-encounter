# v0.12.1 — a trajectory, not an agent

Documentation only. No code, ontology or configuration changes.

## What this memory holds is a trajectory

The documentation used to call the thing this memory holds an "agent". It is
a different kind of thing, and it now has its own word: a **trajectory**. That
means the model bound to this memory, identified by what it has lived rather
than by its configuration.

The difference matters in practice. An agent, as the field uses the word, is
a role you can clone to scale, reset when it drifts, or give a shared memory
pool. Done to a trajectory, each of those does something else. A copy of the
graph continued elsewhere becomes a different trajectory from its first new
encounter: a sibling that shares a past, not a replica. Resetting one ends it.
And two different trajectories writing into one graph produce a record that
describes no one who lived it.

The rule that follows: **one graph holds one trajectory.** Sessions open at
the same time on one graph are that trajectory's own sessions, which the
process layer records as concurrent sessions.

Where the documentation used "trajectory" for the conversation's recent turns
the meaning matcher reads, it now says that. The `trajectory` parameter on
`infuse` and `KENNING_ENCOUNTER_INFUSE_TRAJECTORY_TURNS` keep their names, so
no hook needs to change.

## Changed: the recommended hook scope

The README advised wiring the hooks only in a project's
`.claude/settings.json`, never globally, as if meeting other work were a leak.

**Recommended now: wire the hooks globally**, in your user-level
`~/.claude/settings.json`, so every Claude Code session on the machine is an
encounter of the same trajectory. A trajectory becomes what it is through
varied encounter, not a single repository. Work in an unrelated project is not
contamination: the infusion selects what bears on each prompt and is silent
when nothing does.

**Per-project wiring is still a choice,** for a deployment that should hold a
memory of its own. What grows there only ever meets one kind of work, which is
a cost, not a safety default.

## Fixed: the operations manual taught the old process layer

The HOWTO still described how sessions were ordered before v0.10.0: an
`INSTANTIATED_AFTER` edge, a `genesis_anchor` in the re-entry payload, and a
`dissolved_at` timestamp on encounters left open. None of those exist now. It
describes the current model: a `Locus` per session keyed by the `session_id`
you pass, `OPENED` and `NEXT_LOCUS`, encounters in different sessions left
unordered rather than ordered by wall clock, and an unsealed encounter carrying
no mark but its missing seal. `Locus` is added to its type list.

## Upgrading

Nothing to do. If you wired the hooks per project and want one trajectory
across your work, move the hook entries to `~/.claude/settings.json`, keeping
the same graph.

As with everything here, this is described and tested only for a trajectory:
a model bound to its memory through Claude Code hooks.
