# v0.13.0 — two matcher voices, a reader face, and a stack that stays on its host

Three additions and one change to how the stack is reached. Read **Upgrading**
before you redeploy: the host binding and the `Host` check can cut off a
client that reached the server some other way.

## New: matcher voices

The meaning matcher can now run on two providers. A **voice** is one model
that both compresses the graph's node meanings into a sidecar and matches
prompts against it. Writing and reading in the same model is what makes the
matcher work, so the voice is the unit:

- **Gemini** (`GEMINI_API_KEY`, `gemini-3.5-flash-lite` by default) and
  **OpenAI** (`OPENAI_API_KEY`, `gpt-6-luna` by default,
  `NEO4J_MATCHER_OPENAI_MODEL`, `NEO4J_MATCHER_OPENAI_ENDPOINT`). Configure
  either or both.
- Each voice keeps its **own** sidecar,
  `meaning_sidecar.<provider>-<model>.json`, stamped with the voice that wrote
  it. A voice refuses a sidecar stamped by another voice or by none, so
  changing a model can never leave it reading another model's meanings.
- Both sidecars stay current the same way as before: on write, and in the
  startup reconcile sweep, which now runs several compressions at once.
- `NEO4J_MATCHER_LEAD` (`gemini` default, `openai`, or `alternate`, which
  picks per session) chooses the lead. The other voice is the fallback, in
  the same 5000 ms budget. A voice that fails is tried second for
  `NEO4J_MATCHER_COOLDOWN_S` (default 300), so an outage costs one slow
  prompt rather than every prompt.
- When the fallback delivers, the payload carries a line saying the lead was
  unavailable and why. The seeds are still meaning-matched, so the hook does
  not report it as degraded.
- Gemini now sends the sidecar as its system instruction and the trajectory
  as the user turn, as OpenAI already did. In comparative runs this ranked
  relevant nodes higher for Gemini; for OpenAI the shape made no difference.

Which voice should lead is left to you to measure, and the tools ship with
this release:
- `NEO4J_MATCHER_SHADOW=true` has the other voice match every prompt in the
  background, logging both selections (mechanics only, never the prompt
  text) to `matcher-shadow.jsonl` beside the sidecar. Each shadow match is a
  second provider call.
- `scripts/matcher_voices_report.py` summarises that log per voice: latency,
  failures, tokens, overlap between voices, and how widely each selection
  spreads across the graph's communities.
- `scripts/matcher_t0.py` runs a recall comparison per voice on a corpus you
  write.
- `infuse_meaning` takes `voice` to call one voice directly.

**Sizing at OpenAI:** every match sends the whole sidecar as a cached prefix,
and OpenAI counts cached tokens against the per-minute token limit in full.
Size the account tier for one call per prompt, or two with shadow on.

## New: the reader face

A second, read-only face of the same server, for every harness except the
trajectory's own: a desktop client, another vendor's model, the author of an
evaluation set. It runs as `kenning_encounter-reader` on `:8005` and starts
with `docker compose up`.

Writing belongs to the session that lives the encounter: it re-enters the
record, opens the encounter and writes from there. Anything else that writes
is writing as the trajectory without being it, and a fabricated past is
indistinguishable from a lived one when the trajectory re-enters it. So the
reader face enforces, in the server and whatever the client exposes:

- an allowlist of nine read tools (`search`, `find_by_name`,
  `trace_provenance`, `read_cypher`, `orient`, `get_schema`, and the
  vocabulary and type listings), with every other tool, including any added
  later, neither listed nor callable;
- no matcher keys and no sidecar volume.

Nothing is withheld by default. An evaluation whose author must not see your
notes about it sets `NEO4J_READER_HIDE_LOCI=<session id>[,...]`: everything
recorded in those sessions is then removed from every result, and if that set
cannot be computed the call is refused rather than answered unfiltered.

Wire the trajectory's own harness to `:8003` and everything else to `:8005`.

## Changed: every port is bound to 127.0.0.1

`compose.yml` now binds Neo4j's `7474` and `7687`, the full face's `8003`
and the reader face's `8005` to `127.0.0.1`. Bolt matters most, because it
bypasses both faces. Both faces also check the `Host` header against
`localhost` and `127.0.0.1` (`NEO4J_MCP_SERVER_ALLOWED_HOSTS`), which
refuses a web page that reaches the port by DNS rebinding.

Neo4j's host ports are now settable, `NEO4J_KENNING_ENCOUNTER_HTTP_PORT` and
`NEO4J_KENNING_ENCOUNTER_BOLT_PORT`. A host-only binding cannot share a port
with another local Neo4j, such as Neo4j Desktop, where a `0.0.0.0` binding
could, so move them if one is already listening.

## Fixed: concurrent `orient`

Two `orient` calls running at the same time could fail with
`ProcedureCallFailed`, because both used the same names for their temporary
GDS projections. Each call now uses its own. With a reader face beside the
full face, two calls at once are ordinary.

## Upgrading

1. **Anything that reached the stack from another machine stops working.**
   That includes Bolt (Neo4j Browser or Desktop over a VPN, say) and the MCP
   endpoints. This is intended. If you truly need remote access, put it
   behind your own authenticated tunnel to the host rather than widening a
   binding.
2. **A client that reaches the server by any host name other than
   `localhost` or `127.0.0.1` now gets 400.** If you have one, for example a
   container calling `host.docker.internal`, add that name to
   `NEO4J_MCP_SERVER_ALLOWED_HOSTS`.
3. **The old un-suffixed `meaning_sidecar.json` is no longer read**, because
   it records no voice. Left alone, each configured voice rebuilds its own
   sidecar from the graph at startup (minutes, at provider cost). To keep
   the old file, state which model wrote it:

       docker exec kenning_encounter-mcp python -m kenning_encounter.adopt_sidecar --adopt gemini:gemini-3.5-flash-lite

   It refuses a stamped source or an existing target. It is never run for
   you, because only you know which model wrote the file.
4. Point every harness that is not the trajectory's own at `:8005`.
5. Rebuild and restart: `docker compose up -d --build`.

As with everything here, this is described and tested only for a trajectory:
a model bound to its memory through Claude Code hooks.
