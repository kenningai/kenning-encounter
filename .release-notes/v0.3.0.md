# v0.3.0 — session-scoped writes, per-session chains, the unsealed set

This release makes the memory safe under **concurrent sessions** — multiple
agent runs over one graph at the same time — by scoping every write to the
session that makes it.

## Session-scoped write targeting

`advance_encounter` records the new encounter against the calling session's
MCP session id. `close_encounter` and `create_entities` address **that
session's** encounter — never a global "latest". A concurrent session can no
longer capture another's seal or have nodes mis-anchored into its encounter.
Both tools accept an explicit `encounter` name for the one recovery case: the
server restarted and lost session state mid-encounter.

## Per-session chaining with a connected spine

Each session's encounters form one fork-free `NEXT_ENCOUNTER` path. A new
process edge, **`INSTANTIATED_AFTER`** (auto-written, like the rest of the
spine), anchors each session's first encounter to whichever encounter was
latest when the session began — writes are serialized, so that order is exact.
Concurrent sessions branch without corrupting each other, and the whole spine
stays one connected, temporally ordered structure.

## The unsealed set

The single "dissolution marker" is replaced by the full **unsealed set**:
every encounter with no closing summary, annotated with last-activity time,
returned by both `orient` and the re-entry payload. An unsealed encounter may
be a live concurrent session or a crashed run — the graph cannot tell which,
so it reports and does not guess.

## Honest crash marking

When the server shuts down with a session's encounter still open, it stamps a
mechanical `dissolved_at` timestamp — and nothing else. No summary is ever
auto-written: a summary is the session's own account of its work, and
fabricating one for a crashed run would corrupt the record. A session that
returns and seals via the explicit `encounter` handle clears the mark.

## The spine is never deletable

`delete_entities` now refuses `Encounter` nodes — enforced in the tool and
structurally in the delete query (names are not unique across labels, so the
sweep excludes the spine even on a name collision). Deleting an encounter
would orphan everything recorded in it and falsify the chain.

## Always-stateful HTTP

The stateless-HTTP option is removed. An encounter depends on the state that
preceded it, so HTTP sessions are always stateful: the `Mcp-Session-Id`
carries the session identity and the `DELETE` teardown is honored.
