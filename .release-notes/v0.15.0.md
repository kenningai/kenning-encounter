# v0.15.0 — a matcher fallback that answers, Gemini voices that think, a reader that only reads

Three changes to the meaning matcher and one to the reader face. No
migration. Read **Upgrading** if you run the reader face against a new
graph, or if you set the hook's timeout yourself.

## Changed: the fallback voice gets a chance when the lead hangs

With two matcher voices configured, the lead is tried first and the other
is the fallback, inside one shared time budget. A lead that failed quickly
left the fallback plenty of time. A lead that hung until its timeout spent
the whole budget, so the fallback was skipped and the prompt fell back to
lexical seeds while a healthy voice sat unused.

- A lead still silent `NEO4J_MATCHER_HEDGE_MS` after it began (default
  `3700`) now starts the next voice alongside it. The first valid selection
  wins and the other call is cancelled. A lead that fails starts the next
  voice at once, as before. `0` restores the one-after-another chain.
- A lead overtaken by its fallback counts as failed for the cooldown, so the
  next prompts lead with the voice that answered.
- `NEO4J_MATCHER_TIMEOUT_MS` now defaults to `8500`: one hedge interval plus
  one full fallback call. Every voice gets only what remains of it, so
  nothing outlives the budget.
- The hook's own timeout, `KENNING_ENCOUNTER_INFUSE_TIMEOUT`, now defaults to
  `12` seconds, above that budget. If you set it yourself, keep it above the
  matcher budget plus a cold first call, or a slow fallback costs the whole
  infusion, lexical seeds included.
- The `[matcher lead unavailable …]` line now appears only when the
  fallback voice delivered. When the lead answers after its fallback failed
  or was overtaken, there is no line, because nothing fell back. The line
  still never names a voice.

On a prompt where the lead hangs, the infusion now arrives a few seconds
later than usual, with meanings, instead of on time without them.

## New: Gemini voices that think

`NEO4J_MATCHER_THINKING` (default empty) sets the Gemini voice's
`thinkingLevel`. Empty sends nothing, exactly as before. Set it for a model
that cannot turn thinking off: `gemini-3.8-flash`, for example, accepts
`low`, `medium` and `high` and refuses `minimal`. Use `low` for the
matcher, whose answer is a short list of numbers.

With a level set, the voice:

- sends it as `thinkingConfig.thinkingLevel`;
- leaves `temperature` at the model's default, as Google advises for Gemini
  3 models steered by thinking level;
- gets extra room on its output cap, because thinking and the answer share
  `maxOutputTokens`, and a call that spends the cap thinking returns no
  answer at all;
- never reads a thought part as its answer.

An unknown level stops the server at startup, instead of failing every
prompt with a 400.

A new model is a new voice: it compresses its own sidecar. Switching
`NEO4J_MATCHER_MODEL` starts that sidecar from empty, and the startup sweep
fills it in the background. To have it complete before the switch, build it
first with `scripts/build_meaning_sidecar.py --model <model> --thinking
<level>`. The default model is unchanged, so upgrading does not recompress
anything.

## Changed: the bulk sidecar build matches the server

`scripts/build_meaning_sidecar.py` now reads the same corpus as the
server's own sweep: no process-layer nodes, in creation order. It
previously left out only `Encounter`, so it compressed every session node
too (paid calls whose results the server then removed), and it ordered by
name where the server builds in creation order.

## Changed: the reader face writes nothing, startup included

Both faces used to create the graph's indexes and constraints at startup,
the read-only face included. The reader now skips that and logs that it
did. The schema belongs to the full face, the only one that writes. This
also ends a schema-lock deadlock Neo4j could report, and then retry, when
both faces started at the same moment.

## New: `KENNING_ENCOUNTER_FULL_ALLOWED_HOSTS`

A proxy on the same host in front of the full face (a tailnet's local
publishing, say) forwards its own host name, which the Host-header check
refuses. Add it in `.env` as a comma-separated list that keeps
`localhost,127.0.0.1`, and the name stays out of your repository. The
default is unchanged.

## Upgrading

1. **Rebuild and restart:** `docker compose up -d --build`.
2. **Against a new, empty graph, start the full face first.** The reader no
   longer creates the fulltext index, so until the full face has run once,
   the reader's `search` finds none.
3. If you set the hook's timeout to `10` yourself, raise it to `12`.

As with everything here, this is described and tested only for a trajectory:
a model bound to its memory through Claude Code hooks.
