# v0.1.0 — genesis

Initial release of `mcp-agent-memory`: a FastMCP server backing an encounter-sequential memory graph over Neo4j for an LLM agent that accumulates its own structured working memory across sessions.

What's in this baseline:
- **Process spine** — a guarded `Encounter` chain (`advance_encounter` / `close_encounter`) as the sole writer of `NEXT_ENCOUNTER`; no forks.
- **Bounded write paths** — `create_entities` / `create_relations` / `delete_*` for the semantic (Observation / Question / Hypothesis / Concept / Note) and reference (Component / Citation) layers, with MERGE idempotency, auto-set `t_created`, and auto-anchored provenance (`RECORDED` / `CONSULTED`).
- **Self-instruments** — `orient` (one-call GDS spread — PageRank / Betweenness / Louvain / WCC — over a coherence-only projection, lifecycle-managed); the individual `gds_*` tools; `read_cypher` (EXPLAIN-gated read-only), `search`, `find_by_name`, `list_vocabulary`, schema/type introspection.
- **Re-entry payload** — recent encounters, open Questions, live Hypotheses, recently-touched Concepts, the coherence edges among them, and a dissolution marker for an unsealed predecessor.
- **Operations manual** — `agent-memory://howto`, served from the package.

Quality gate at genesis: 54 unit tests passing, `pyright` clean. Brought under version control via `/genesis --adopt`.
