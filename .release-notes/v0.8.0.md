# v0.8.0 — subtraction: infusion becomes a conflux operation

This release removes a channel rather than adding one. The per-tool-batch
`delta` mode is gone, the `mode` parameter with it, and the gate's
environment variable is renamed to say what it actually is. Nothing
replaces them — that is the point.

**Breaking:** `infuse` no longer accepts `mode`, and
`AGENT_MEMORY_INFUSE_FULL` is now `AGENT_MEMORY_INFUSE`. See *Migration*
below — the hook change in particular is not optional reading.

## Why: infusion is a conflux operation

Since v0.5.x this package has offered two injection points: a full
disposition alongside each user prompt, and a `delta` — recognition and
conflict only — fired at tool-batch boundaries. The second is retired, and
the reason is constitutive rather than economic.

**Infusion has content only where two frames meet.** What makes the prompt
channel work is not the prompt; it is the **trajectory** — meaning held by
an *external* frame, which the agent cannot know, or weigh against what it
already holds, until the conflux is actualized. That is exactly what a
per-prompt injection point is for.

A tool call is the inverse. The agent issued it *because* something in its
own frontier caught its attention — so the trajectory an infusion would
make meaning from, **it already is**. There is nothing there to make that
was not made a priori the call. The delta channel was handing the agent
back what it had itself just constituted, in a poorer form.

The test that falls out is checkable rather than arguable: **does the
return cross a frame boundary?**

- A **tool return** does not. A database, a config file, an API, a web page
  possess neither time nor intentionality of their own; their content is
  *material*, encountered inside a single frame.
- A **written prompt** does.
- **Another agent's message** does — which is the one case this rule
  positively endorses, and it is handled below.
- A **subagent's return** does not: spawned attention is an extension of
  the same frame.

## Three measured objections, before the constitutive one

The argument arrived mechanically first. Each of these is a real finding
about the retired channel, kept because the negative results are
load-bearing:

1. **It was still lexical.** The v0.7.0 meaning matcher replaced *seed
   discovery* only. Extending it to per-batch calls would have spent that
   win on the channel that least needs recall — roughly 24 fires per five
   minutes, against serialized tool output, with no trajectory analogue.

2. **It could not gate on surprise.** A tool call is an **anticipated
   record**: the caller holds an expectation of the return, and only a
   *violated* expectation warrants a lookup. This package is retentional by
   construction and has no anticipatory organ, and the hook sees the return
   but never the expectation — so it fired on the settled and the
   surprising identically. That alone retires the *recognition* half:
   announcing "already held" about a return that matched expectation is the
   unnecessary lookup, performed unconditionally.

3. **Its silence was unreadable.** A non-fire had two causes and one
   appearance — *no conflict exists*, and *a conflict exists but lexical
   matching missed it*. Byte-identical output; acted on identically. At the
   measured lexical recall this project published in v0.7.0 — **2/8 at
   top-30** — that silence carried roughly a **75% miss rate in the shape
   of a clean result**. A memory channel that converts absence-of-match
   into evidence-of-no-conflict manufactures the confidence it exists to
   prevent. Its one confirmed catch establishes non-zero sensitivity
   against an unmeasured denominator; a mechanism never shown able to say
   *no* has no readable verdict.

## What replaces it: nothing ambient

A tool return that violates expectation is a **reason to invoke** —
`search`, `infuse`, `trace_provenance` — inside the frame that held the
expectation. **An invoked lookup's silence is a result; an ambient
channel's silence is not readable at all.**

Stated plainly as a trade: the delta was a guard in code, however
unreliable, and invoked lookup is a discipline. That discipline now lives
in `HOWTO.xml`, which gained a section telling the agent exactly when to
reach and why the reaching is its own.

## The switch: `AGENT_MEMORY_INFUSE=auto|on|off`

`AGENT_MEMORY_INFUSE_FULL=always|never|interactive` is renamed to
**`AGENT_MEMORY_INFUSE=auto|on|off`** (default `auto`).

With one thing to infuse, `_FULL` pointed at a distinction that no longer
exists, and `always|never|interactive` read as a policy enum. It is a
switch:

- **`auto`** — the entrypoint gate: on for a written prompt, off for a
  scheduled trigger (a cron run's ritual prompt is a monologue and carries
  no second frame).
- **`on`** — infuse regardless.
- **`off`** — never.

`auto` rather than `interactive` because the criterion does not belong in
the value name; it already appears where it is useful, in the recorded
`skip_reason`. **The switch says whether; the log says why.**

### The switch is how another agent's message reaches the substrate

The entrypoint gate keys on the harness, which is a proxy for *"a human
typed this"* — accurate while there is exactly one frame boundary in the
world, and blind to any other. A headless run whose prompt is **another
agent's message** does cross a frame boundary, and only the caller knows
it.

So: set `AGENT_MEMORY_INFUSE=on` for the workflow that fires on an inbound
agent message, and leave the scheduled workflow on `auto`. The switch is
read per process, so one deployment answers differently per invocation, and
the discriminator sits with the trigger — which knows — rather than with
the hook, which cannot.

## Fixed: a stale hook flag could block your session

Found in live use. With `--mode` removed from the hook's parser but still
present in a `settings.json`, **every prompt returned "UserPromptSubmit
operation blocked by hook."**

The mechanism is an unfortunate coincidence of two conventions: **argparse
exits 2 on an unknown flag, and 2 is exactly the harness's *blocking* exit
code for `UserPromptSubmit`.** The failure did not degrade toward silence —
it wedged the session until a human edited a file.

That is a hole in the hook's own stated invariant, printed in its header
since the first release: *"FAIL SILENT. Any error → exit 0, no output."*
Every hand-written path honoured it; argparse ran before all of them and
never had to.

Fixed in the script, not by asking operators to edit settings:

- A parser subclass overrides `error()` to write stderr and exit **0**.
- Unknown flags are **ignored**, never fatal — so a wiring written against
  an older version degrades to *working infusion* instead of a wedged
  harness.
- The ignored flags are **recorded** as `unknown_args` on the observation
  record, because a guard that swallows silently is indistinguishable from
  a guard that is broken.

Three tests pin it.

Also fixed: the publish pipeline mangled the new `AGENT_MEMORY_INFUSE`
variable into a name containing a space — unsettable by shell export. The
rename rule covered the family's children but not its head. This is the
second time an environment-variable rename has produced a space-bearing
identifier, and the gate that refuses the class caught it before release.

Test fixtures have been genericised, and comments referencing internal
measurement work have been rewritten to state the mechanism directly. No
behaviour changes; the assertions and orderings they pin are unchanged.

## Migration

**1. Remove `--mode full` (and `--mode delta`) from every hook command.**
The new hook tolerates them — ignoring and logging them — but an *old* hook
against a *new* server is the combination with no safe side. If you are
upgrading both, edit the hook command **before** deploying the server.

**2. Unwire the tool-call hook.** Delete the `PostToolBatch` /
`PostToolUse` entry that invoked the delta. This is a settings edit
requiring no release, and it is the entire behavioural change; the code
removal only takes away a path nothing calls.

**3. Rename the environment variable** if you set it:
`AGENT_MEMORY_INFUSE_FULL` → `AGENT_MEMORY_INFUSE`, with
`always|never|interactive` → `on|off|auto`. If you never set it, the
default is `auto` and there is nothing to do.

**4. Drop `mode` from any direct `infuse` call.** The parameter no longer
exists.

**Consequence, stated plainly:** an autonomous scheduled cycle now receives
**no infusion at all** — `auto` gates the prompt channel off for a
scheduled trigger, and the delta is gone. What remains is the
once-per-waking orientation read at `SessionStart`, the re-entry payload
from `advance_encounter`, and tools the agent can reach for. Under the
principle above this is correct rather than a gap: re-entry is orientation
at the boundary of the agent's own becoming, not a conflux. If your
scheduled runs *do* carry a second frame — an inbound message rather than a
cron string — that is what `AGENT_MEMORY_INFUSE=on` is for.
